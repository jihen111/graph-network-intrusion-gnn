# Morning Report — Temporal Graph Intrusion Detection

## Executive summary

Built a reproducible CPU portfolio project for flow-level network intrusion detection with host-level temporal graphs. The primary NF-UNSW-NB15-v2 table was not usable for the requested graph/time protocol because the downloaded feature-only parquet had no source/destination endpoints or event timestamps. The project therefore uses the CIC-IDS2017 `GeneratedLabelledFlows` CSV archive, which retains IPs and timestamps. No endpoint or time values were fabricated.

The final benchmark used **40,000 labelled flows**, **94 encoded features**, **10 UTC-aligned hourly test windows**, and three model seeds. All reported metrics are from the chronological test partition. The flow-only Random Forest outperformed E-GraphSAGE at the conventional 0.5 threshold on this sample; the benign-only graph autoencoder had higher recall but a high false-positive rate. The run does not demonstrate a graph-model advantage or production readiness.

## What was delivered

- Modular Python pipeline for data loading, label-aware sampling, train-only feature preprocessing, temporal splitting, directed host-flow graph construction, model training, evaluation, and visualization.
- Edge-conditioned GraphSAGE flow classifier, benign-only topology-based graph autoencoder, and flow-only Random Forest baseline.
- CPU experiment configuration: 40,000-flow sample, three seeds, up to eight epochs, and patience-two early stopping against validation loss. The best validation checkpoint is restored; test data is not used for stopping.
- Label-efficiency study (1%, 5%, 10%, 25%, and 100% of training labels), edge-feature and preprocessing ablations, per-attack metrics, graph summaries, and flagged test subgraph.
- Two notebooks (`01_eda.ipynb`, `02_graph_analysis.ipynb`), an English README, design decisions, 15 interview-learning notes, architecture diagram source/image, deterministic data download script, pinned dependencies, and 10 unit tests.
- Main figures: `results/label_efficiency.png`, `results/graph_comparison.png`, and `results/attack_subgraph.png`. Machine-readable outputs: `results/metrics.json`, `results/label_efficiency.json`, `results/ablation.json`, and `results/graph_analysis.json`.

The notebooks are structurally validated and their Python cells compile. The actual benchmark metrics and figures were generated by the experiment script; Jupyter notebook execution was not separately timed or embedded into notebook outputs.

## Dataset and protocol

- Source: CIC-IDS2017 `GeneratedLabelledFlows.zip`, fetched from the public Hugging Face mirror documented in `data/README.md`; the official CIC dataset documentation is linked there as well. PCAP files were not downloaded.
- The loader excludes unlabelled rows before sampling. Flow IDs, raw IPs, ports, timestamps, and labels do not enter the numeric model feature matrix; host IPs define graph nodes. Ports are retained only as coarse edge categories.
- CIC timestamps have no timezone offset. They are interpreted as UTC, sorted, grouped into whole one-hour graph windows, then assigned chronologically to train/validation/test. Preprocessing is fitted on training flows only.
- Split counts: train **22,164** flows (3,490 attacks), validation **7,586** (307 attacks), test **10,250** (4,083 attacks). Whole-hour partitioning means the row proportions are not exactly 60/20/20.
- Test supports by attack type: Bot **25**, DDoS **1,839**, PortScan **2,219**. These are the only three attack labels present in this chronological test period.
- Timestamp bucketing was compared between the prior floating-point calculation and the final integer-second implementation on **2,830,743** parseable CSV timestamps: **0 bucket mismatches**.

**Interpretation:** the Random Forest is marginally better than E-GraphSAGE in F1 (0.443 vs. 0.410) and PR-AUC (0.916 vs. 0.871) on this split. None of these results supports a claim of generalization beyond this dataset or deployment readiness.

The curve is non-monotonic; 10% exceeds 100% in this one experiment. This is a diagnostic observation, not evidence that a smaller label budget is generally superior. Scores use the fixed 0.5 threshold.

| Features | Edge features | Test F1 (mean ± population std) | PR-AUC (mean ± population std) |
|---|---:|---:|---:|
| Engineered | Yes | 0.410289 ± 0.003575 | 0.870975 ± 0.048154 |

The no-edge variants produce no positive predictions at threshold 0.5 despite high PR-AUC, indicating a score/threshold calibration issue rather than a lack of ranking signal. Validation-based threshold selection for supervised models is a clear follow-up experiment.

## Graph analysis

The graph summary is calculated on test windows only; fan-out is averaged over active source hosts (sources with at least one outgoing edge), not sink nodes.

| Test subgraph type | Windows | Mean flows/window | Mean hosts/window | Mean active-source fan-out |
|---|---:|---:|---:|---:|
| Benign | 10 | 616.7 | 222.4 | 3.00 |
| Attack-induced | 7 | 583.3 | 2.9 | 1.21 |

The attack-induced graphs in this sample reuse a very small set of endpoints. Their mean active-source fan-out is below the benign value, so this dataset/split does **not** exhibit the illustrative pattern of one attack source scanning many hosts. The E-GraphSAGE flagged-subgraph figure shows a single directed edge in test window 416500, not a multi-host attack path. This is useful graph-construction and visualization practice, but weak evidence for lateral-movement detection.

## Reproduction

From the project root:

```bash
python scripts/download_data.py
python -m pip install -r requirements.txt
python -m src.train --config configs/experiment.yaml
python -m unittest discover -s tests -v
```

To change the sample size, use `python -m src.train --config configs/experiment.yaml --sample 200000`. Use `--sample 0` to process all labelled flows; the full run will take longer. The available outputs are described in `README.md`.

## Limitations and next steps

1. The main model results are based on a deterministic 40,000-flow sample, not a full-data benchmark.
2. The chronological test period contains only three attack classes and few attack host endpoints; broaden evaluation to other time periods/datasets before making general claims.
3. RF and GNN thresholds were fixed at 0.5; future comparisons should select supervised thresholds on validation, then evaluate those thresholds once on test.
4. The attack-subgraph visualization contains one edge; richer labeled attack paths or a second dataset are needed to demonstrate host scanning/lateral movement.
5. The CIC timestamp has no timezone offset; UTC is an explicit convention, not a source-provided timezone.
